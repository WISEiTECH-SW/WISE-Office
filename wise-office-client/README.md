# WISE-Office Clinet

연구소 연구기획팀의 백오피스 클라이언트 레포지토리입니다.

## 🛠️ 기술 스택 (Tech Stack)

-   **Language**: `TypeScript`
-   **Framework**: `Next.js 15`
-   **Style Management**: `Zustand`
-   **Styling**: `Tailwind CSS`
-   **API Communication**: `Axios`
-   **Date Handling**: `dayjs`, `flatpickr`
-   **UI Components**: `lucide-react`, `react-toastify`

## 🏛️ 클라이언트 구조 (Client Architecture)

```
wise-office-client/
└── public/                         # 1. 정적 리소스
└── src/
    └── components/                 # 2. UI 컴포넌트
    └── hooks/                      # 3. 커스텀 훅
    └── lib/                        # 4. 라이브러리 및 유틸
    └── pages/                      # 5. 라우팅 및 페이지
        ├── api/
    └── services/                   # 6. API 서비스
    └── store/                      # 7. 전역 상태 관리
    └── styles/                     # 8. 전역 스타일
    └── types/                      # 9. 타입 정의
```

### 1. 정적 리소스 (`public/`)

-   클라이언트에서 사용하는 이미지, 아이콘, 문서 등의 정적 자원이 위치합니다.

---

### 2. UI 컴포넌트 (`components/`)

-   재사용 가능한 React 기반 UI 컴포넌트가 위치합니다.
-   도메인 또는 기능 단위로 구성되어 있으며, 개별 페이지에서 조립하여 사용됩니다.
-   각 컴포넌트는 상태를 갖지 않고 뷰만 담당하며, 로직은 분리된 훅 또는 store를 통해 처리합니다.

---

### 3. 커스텀 훅 (`hooks/`)

-   `useEffect`, `useState` 등의 React 훅을 기반으로 한 재사용 가능한 커스텀 훅들이 위치합니다.
-   복잡한 비즈니스 로직, API 호출, 폼 제어 등의 반복되는 로직을 추상화하여 코드의 응집도와 재사용성을 높입니다.

---

### 4. 라이브러리 및 유틸 (`lib/`)

-   전역적으로 사용되는 헬퍼 함수, 유틸리티, 상수, 외부 라이브러리 래퍼(wrapper) 등을 포함합니다.
-   날짜 포맷, 공통 에러 처리, API 클라이언트 초기화 등 기술적 의존성이 높은 기능을 분리해 관리합니다.

---

### 5. 라우팅 및 페이지 (`pages/`)

-   Next.js의 파일 기반 라우팅에 따라 클라이언트 URL 경로와 직접 매핑되는 컴포넌트가 위치합니다.
-   URL 엔드포인트를 구성하며, 사용자 인터페이스의 진입점을 정의합니다.

### 5-1. API (`pages/api`)

-   클라이언트의 HTTP 요청을 받아들이는 서버리스 엔드포인트가 위치합니다.
-   프록시 서버 역할로 활용될 수 있으며, 일반적으로는 외부 백엔드오의 직접 통신을 우선합니다.
-   필요 시 JSON 응답 처리, 인증 토큰 검증 등의 간단한 백엔드 로직을 포함할 수 있습니다.

---

### 7. API 서비스 (`services/`)

-   Axios를 기반으로 외부 백엔드 API와의 HTTP 통신을 담당하는 함수들이 위치합니다.
-   각 도메인별로 API 호출을 모듈화하여 재사용 가능하게 구성되어 있습니다.
-   요청 전/후 처리, 에러 핸들링, 인증 헤더 삽입 등의 로직도 포함될 수 있습니다.

---

### 8. 전역 상태 관리 (`store/`)

-   글로벌 상태 관리는 **Zustand**를 기반으로 구현되며, React Context보다 가볍고 직관적인 방식으로 설계됩니다.
-   프로젝트 목록, 사용자 인증 정보, 토큰 등 애플리케이션 전반에 필요한 상태를 중앙에서 관리합니다.
-   상태는 컴포넌트 간에 공유되며, SSR 환경에서도 안전하게 사용할 수 있습니다.

---

### 9. 전역 스타일 (`styles/`)

-   TailwindCSS 기반 전역 스타일 설정 파일 및 커스텀 CSS가 위치합니다.
-   `_app.tsx`에서 전역 스타일이 적용되며, 추가적인 커스터마이징이 필요할 경우 이 디렉토리에 정의합니다.

---

### 10. 타입 정의 (`types/`)

-   프로젝트 전역에서 사용되는 TypeScript 인터페이스 및 타입 정의가 위치합니다.
-   API 요청/응답, 상태 객체, 컴포넌트 Props 등의 타입을 정리하여 타입 일관성과 생산성을 향상시킵니다.
-   코드 자동 완성 및 타입 추론을 통해 안정성을 확보합니다.

## 🚀 실행 방법 (Getting Started)

# 1. 의존성 설치

```
npm install
```

# 2. 개발 서버 실행

```
npm run dev
```
